# 05 · 购物 AI 答案地图（Alexa+ / Rufus / COSMO）

## 能确认的机制，和不能确认的

**能确认**（来自亚马逊官方与 Amazon Science 公开资料，任务当日应刷新一次）：亚马逊购物助手综合 Listing 文本、结构化属性、评论、Q&A 等回答买家的自然语言问题；COSMO 研究的是"意图 ↔ 商品"的常识关系——适合谁、用于什么、什么条件下。

**不能确认、因此不写不承诺**：卖家可写入的权重接口、字段权重、7–14 天刷新期、固定问题数、"完整度 90% 分"、流量分配。第三方 COSMO / Alexa Shopping / Item Highlights 玩法一律当"社区假说"，不当平台规则。

结论：让购物 AI 正确理解页面的方法，就是**把买家真实会问的问题，用它能找到的文字，在页面上直接回答，并写清适用条件与不适合谁**。这与写给人看的好页面是同一件事。

## 答案地图是交付物，不是检查项

格式：

| 买家原话问题（Q_id + 原话） | 页面哪里直接回答（字段 / 五点序号 / A+ 模块） | 回答句原文 | fact_id | 适用条件 / 不适合谁 |
|---|---|---|---|---|
| Q01 "Do these come with pads?" | B3 | "The shelf bra has insert openings and comes without pads: …" | F105 | 全部 child；想要自带垫的买家不适合 |

要求：
1. 问题库前 10 条高频高影响问题，每条都必须在**正文文字**（Title / Highlight / 五点 / Description / A+ 正文）里找到直接回答。图片文字、ALT、视频、后台词、社区 Q&A 只算辅助。
2. 每个主要场景写成"给谁 / 什么场景 / 解决什么 / 什么条件"，出现在五点或 A+ 正文。
3. 明确写"不适合"的情况（条件句），减少误购流量。
4. 结构化属性与文案一致（材质、背型、产地、pack 数）：AI 会同时读两边，矛盾时它不知道信谁。
5. 不写"AI 专用卖点"，不重复堆同一组功能。同一功能在 Title 里出现一次、五点展开一次即可。
6. 搜索联想词进 Title / Highlight 时要成句，不是词串；词串对人对 AI 都是噪音。

## 三类"AI 会问、页面常漏"的问题

| 类型 | 例 | 页面通常怎么漏 |
|---|---|---|
| 排除类 | "Is it supportive enough for a larger bust?" | 只写正面，不写边界，AI 只能回答"页面没说" |
| 选择类 | "Which size if I'm a 36D?" | 尺码表只在图片里，AI 读不到 |
| 条件类 | "Can I sleep in it?" / "Does it work for pumping?" | 五点写"versatile"，没写在什么条件下能 |

## 推荐句自检（内容充分性，不是 AI 模拟）

对前 5 条问题各写一句"如果购物助手要向这类买家推荐本品，它能从页面原文里拼出什么句子"。拼不出来 → 页面缺这句；拼出来的句子含 HOLD 内容 → 页面说了不该说的。这只验证内容够不够，不推断亚马逊会不会检索、引用或推荐。

## 发布后观察（只在用户要求且有权限时）

Alexa+ / Rufus 回读可以作为黑盒实验记录：站点、账号/个性化上下文、提问、时间、引用来源、出现的商品、输出原文。回答变化只是观察，不证明是哪个字段、COSMO 或本次改版导致。真实转化用 Manage Your Experiments 验证。
