# 01 · A+ 策略与模块设计

## 从意图简报到模块序列

Embedded 模式拿到的是已经胜出的方向。A+ 的工作是把它展开成一次有顺序的阅读：**认出（这是给我的）→ 重构（原来我一直在凑合）→ 欲望（想要那个进展）→ 机制（为什么可信）→ 证明（实拍/细节）→ 选择（哪个码/pack）→ 边界（谁不该买）**。不是每个模块都要走完全部，但整套序列要覆盖一次。

一个主购买任务可以有几个各自有证据的场景；选一条主线讲，不删掉有效用途，也不让每个场景变成一个新主张。新场景不能借用另一个场景的证据。

## 客户决策地图（预研合成时填，不是问卷）

| 维度 | 要回答的 |
|---|---|
| 触发 | 什么事让她开始搜 |
| 核心用户 | 谁最需要 |
| 次要用户 | 谁能用但不该主导承诺 |
| 场景 | 何时、何地、什么状态下用 |
| 任务 | 她想取得什么进展 |
| 替代方案 | 她现在用什么 / 怎么凑合 |
| 痛点 | 替代方案难在哪 |
| 结果 | 什么应该变得更容易或更确定 |
| 顾虑 | 为什么可能不买 |
| 决策标准 | 她比什么 |
| 排除条件 | 谁 / 什么情况不该买 |
| 所需证据 | 什么能让承诺可信 |

胜出后把地图压成 `HERO/WIN`（一句条件式推荐）、`QUALIFY/PROVE`（资格、精确 child/pack 事实、证明、比较）、`DEFLECT`（限制与不适合）。

## 按决策问题选模块

先刷新当前账号资格、可用模块、规格上限。只用解决优先问题所需的模块。

| 买家问题 | 可用载体 |
|---|---|
| 这是什么、给谁 | Hero / 全宽图 + 原生文字 |
| 为什么要换掉现在的做法 | 生活场景图 + 文字 / 多图文字 |
| 关键机制在哪 | 热点图 / 真实细节图 |
| 动作怎么做 | 视频或步骤图（真有用时） |
| 适不适合我的情况 | 原生规格、尺码/兼容内容、Q&A |
| 各 child 含什么、差在哪 | pack/内含物视觉 + 原生文字 |
| 买前该知道什么 | 原生文字 + 事实型 Premium Q&A |
| 这个品牌里我该选哪个 | 同品牌真实差异比较图 |
| 品牌代表什么 | Brand Story，不放 child 级事实 |

不用轮播重复一个想法；不用每格都打勾的比较图；不点竞品名；每个主要模块推进一个不同的动作（认出 / 重构 / 欲望 / 机制 / 证明 / 选择 / 边界），不为多样性复活落选方向。

## 文案链

`功能 → 机制 → 买家收益 → 明确限制 → 证据`

不是每句都要五段，但整个模块要说清为什么成立、到哪为止。用买家的话，不堆关键词；不把科学或平台术语转成没证据的收益。开头写买家能想象的具体用法或选择，不自动以 Check / Choose / Plan 开头。A+ 首屏要和 Listing 主购买理由同一条线，往深处走，不为"补充"而换题（费用、洗护等次要话题不做首屏）。

**欲望–事实–边界三段**（贯穿序列，不必每模块重复）：
1. 欲望句：说出为什么想离开旧的凑合。
2. 事实锚：当前产品的机制/事实，让选择可信。
3. 边界句：不该用它做的事，或相邻的别的产品类型。

只有欲望是广告，只有事实是说明书，边界藏到最后是误购风险。

杂项面板（把剩下的规格、洗护凑一格）不做；不相关细节移到合适载体或删。多个事实回答同一个比较或操作问题时可以放一起。

## 标准模块卡（每个正式模块）

```
模块 ID 与当前后台模块类型
主决策问题
核心用户 / 错误用户或用法
适用 child ASIN、站点、语言
fact_id 与 claim_id
原生标题与正文（英文）
画面指令（中文）与可见产品证明
图上文字（如有，≤ 12 词）
产品必须展示 / 不得改变的细节
ALT
桌面与手机构图/裁切
合成人物状态与规则核对
图像生成方式与合成产品/配件状态
产品参考 ID、保真负责人、复核日期、保真状态
禁用主张
负责人
验收测试
可选实验假设
```

关键事实用原生文字。图片证明或说明，不能是尺码、安全、兼容、含不含、pack、使用限制的唯一载体。

## ALT

上限以任务当日核对的平台规则为准（当前快照：A+ SP-API 100 字符，需刷新）。

写法：`可见主体 + 可见产品 + 可见特征/动作 + 必要场景`。每图一句自然句、只写看得见的、不藏性能/认证/尺码/兼容/比较、不做关键词表、pack/颜色/配件只在可见且该图属于该 child 时提、不依赖 ALT 传达关键事实、不宣称 ALT 有独立 AI 权重。

## AI 与合成图像

- AI 可以在权利与当日平台规则允许时生成人物或环境。
- 产品本体用实拍或受控产品参考；不改形状、界面、扣具、连接方式、数量、颜色、比例、覆盖、内含物。
- 机制与材质主张优先实拍微距。
- 指定产品保真负责人，逐图对样。
- 每张图记：生成方式（real_photo / edited_real_photo / composite / AI_person_or_scene / AI_product_or_accessory / unknown）、合成人物、合成产品/配件、产品参考 ID、适用 child、保真负责人与日期、保真状态（PASS / HOLD / BLOCKED）、平台披露规则来源与日期、所需披露动作。
- `unknown` 或任何未解的产品/配件/数量/接口/标签/颜色/比例差异 → 阻塞消费者可见使用。AI 人物不授权改产品。文案或 ALT 不能修复假产品图。

## Brand Story

回答"品牌代表什么"，不放 child 级事实。历史陈述必须有来源绑定；多年销售观察可以决定模块优先级，但不能替代当前版本的产品证明。新品、转售、无历史：写现在的承诺与做法，不发明创始故事。

## 实验边界

已知的事实、合规、身份、范围、可访问性、手机端缺陷是修复项，不是实验候选。只在两个都真实、都有证据的说服表达之间做实验。真实转化用 Manage Your Experiments 验证；模型偏好不证明转化。
