# 03 · 发散生成：四视角文案员

目的：先写出 3–4 套**互不相同、都能站住**的完整首屏，再让买家评。不是写一稿然后改三遍。

## 共同任务书（写进 `BRIEF_copywriter.md`，prompt 只给路径）

把共同要求写进文件，每个文案员的 prompt 只包含：视角一句话 + 文件路径 + 输出路径。这样做的原因：prompt 短，敏感品类下不易被平台拦截；四人拿到的事实完全一致。

任务书模板：

```
# Copywriter 共同任务书（<产品>，<日期>）

产品：<一句话身份>，ASIN，站点。

## 必读（按顺序）
1. 04_fact_ledger_v1_delta.md —— 最重要。"真相底板"分 SAFE / CANDIDATE / HOLD：只能用 SAFE 与 CANDIDATE，HOLD 一律不写。含老板刚回答的设计初衷、改版、多年销售事实。
2. 00_fact_ledger_v0.md —— 事实台账。引用任何事实都标 fact_id。
3. 02_buyer_question_bank.md —— 买家原话问题、抱怨/夸赞、搜索联想、人设。
4. 01_competitor_teardown.md —— 矩阵（尤其"真正分叉的轴"）、取舍表、竞品内容缺口。

## 交付物（写入 05_draft_Wn.md，UTF-8）
1. 一句话主线（中文）：押的主购买理由、对谁说、明确不对谁说。
2. 英文消费者文案：

   - Item Highlight：≤ <阶段 0 查到的上限> 字符，尽量用满，同上规则；成句，不是逗号规格串。
   - 5 条 Bullet：每条 ≤ 230 字符（推荐格式“大写短标题 — 正文”，可以不用）；每条只解决一个买家问题；限制条件写在同一条里紧挨对应功能。
   - Product Description：≤ 900 字符。
   - （仅当范围含 E）A+ 首屏方向：标题 ≤ 60 + 正文 ≤ 200 + 中文画面指令（只用真实实拍/线框，不许 AI 生成产品）。这是给 A+ 规划器的草案。

4. 中文说明 ≤ 400 字：为什么这样写、放弃了什么、最没把握的三句、问题库前 5 条各在哪句回答（完整答案地图由主智能体在裁决后统一做一次）。

## 硬规则
- 只写英文消费者文案 + 中文说明；不写流程、合规声明、内部标签。
- HOLD 禁词表（含同义改写）：<从三档表生成，逐词列出>。
- 限制条件（"不含 X"、"轻支撑"）不能写成孤零零的负面，要写成有理由的选择（引用对应 fact_id）。
- 需要让"不该买的人"读完能自己判断不该买，同时不吓跑主力买家。
- 英文像目标市场品牌页面的人话，不像说明书；避免以 Check / Choose / Plan 开头；不用 comfortable / perfect / versatile / premium 等空词代替机制。
- 不访问网络。写文件确保 UTF-8。

## 最终回复只给
文件路径、Title 字符数、Highlight 字符数、五条各字符数、HOLD 命中数（应为 0）、最没把握的三句。
```

| 代号 | 视角 | prompt 核心句 |

| W1 | 场景任务型 | "从买家'那一刻要完成什么'出发。首屏讲一个具体时刻里的动作与进展（凌晨三点单手解开、出门前两分钟套上），不讲参数。" |
| W2 | 对比替代型 | "从'买家现在怎么凑合'出发（取舍表里的替代方案）。讲本品相对那种凑合减少了什么负担，只用取舍表有依据的比较，不点竞品名。" |

## 为什么要四稿而不是一稿三改

- 四稿在同一问题上排序相反（例：主力买家喜欢的句子恰好让"不该买的人"误判），这个分裂本身就是第二轮要问老板的题。
- 一稿三改会收敛到写第一稿的人的偏好；四稿让买家评审有真正的选择。
- 破惯例稿通常不会整体胜出，但常贡献 Title 结构或 A+ 标题。

## 常见失败与修正

| 失败 | 修正 |
|---|---|
| 四稿趴在一起，都是"品牌 + 品类 + 材质 + 功能"模板 | 视角句没写具体；给 W1 一个具体时刻，给 W4 一份"禁止使用的通用词表" |
| 某稿 HOLD 命中 > 0 | 回炉重写该句（≤ 1 轮，计入预算）；仍不过由主智能体改写并标注 |
| 某稿无 NEEDS PROOF 标注但有未绑定句 | 真相检查器判 FAIL，回炉（同上） |
| 平台拦截（敏感品类） | 缩短 prompt、身体描述换功能描述、“扮演”改“评估”、重试一次（计入预算）；仍失败由主智能体代写并声明 |
| 文件写成 UTF-16 | `file` 检查，`iconv -f UTF-16 -t UTF-8` 转换 |
