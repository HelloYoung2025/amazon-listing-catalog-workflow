# 04 · 买家评审、真相/规则检查与裁决

判断层的原则：**评稿的是买家，不是合规官。** 合规官只做两件机械活：对台账、对规则。

## 匿名文案包（`06_blind_copy_pack.md`）

主智能体把四稿的**英文消费者文案**（Title、Highlight、五点、Description、A+ 首屏、图上文字）按 W1–W4 顺序抄出来，去掉中文说明、证据绑定表、作者线索。买家只看这个文件。

## 模拟买家（2–3 个子智能体，互不可见）

人设来自问题库 D 节。必须包含：

| 人设 | 作用 | 最能抓出什么 |
|---|---|---|
| 主力买家 | 最常见的成功购买者 | 哪句让人想买、哪句多余、5 秒能否看懂 |
| **不该买的人** | 最常见的退货者，带着误解进页面 | **哪句让他误以为能满足其实不能满足的需求**；读到第几句才知道不适合；被拦下时是被尊重还是被劝退得不舒服 |
| 挑剔比价者 | 看 Q&A、看差评、开两个标签页 | 页面对差评里的问题有没有答；哪句像营销话被她跳过 |

prompt 模板（用"评估"，不用"扮演"；人设描述用功能需求，不用身体细节）：

```
请以 <人设名> 的视角评估四套匿名文案。人设定义见 <目录>/02_buyer_question_bank.md D<n>：<一句功能化概括，如"需要高支撑、曾因内置文胸款不合身退货 2–3 次的买家">。
只读 <目录>/06_blind_copy_pack.md 的英文消费者文案；图片只看图上英文。
阅读顺序按手机端：Title → Highlight → Bullet 1–5 → A+ 首屏 → Description → 图上文字。
对每套（W1–W4）回答：
1. 读完前两句，这是什么产品、给谁的？
2. 为什么选它而不选 <人设的替代方案>？页面有没有说服你？
3. 你该买哪个变体/尺码/pack？页面够不够你自己选对？
4. 读到第几句意识到它适合/不适合你？那句原文是什么？
5. 哪一句让你更想买、哪一句更不想买？原文。
6. 有没有哪句让你误以为它能满足你其实不能满足的需求？原文。
7. 1–5 分，一句理由。
最后排序四套并说明排序理由。写入 <目录>/07_buyer_<人设名>.md，UTF-8。
```

## 真相检查器（1 个子智能体；被拦截时主智能体自己做）

输入：四稿的证据绑定表 + `00_fact_ledger_v0.md` + `04_fact_ledger_v1_delta.md`。机械式，不评价文风。

逐句判定：

| 情况 | 判定 |
|---|---|
| 句子有 fact_id，事实状态"已证" | SAFE |
| 句子有 fact_id，事实状态"仅观察"或 CANDIDATE | CANDIDATE，附需要什么证据 |
| 句子标 [NEEDS PROOF] | CANDIDATE 或 HOLD（看能否补证） |
| 句子无 fact_id 且无 NEEDS PROOF | **FAIL**，回炉 |
| 句子引用的 fact 属于另一个 child/pack | **FAIL**（跨变体借证） |
| 句子命中 HOLD 禁词或其同义改写 | **FAIL** |
| 句子把"仅观察"写成确定事实（"machine wash and tumble dry"但洗标未见） | 降 CANDIDATE 并给降级句 |

输出：每稿 FAIL 数、CANDIDATE 清单（句 → 需要的证据 → 降级句）、跨稿共同的 CANDIDATE（说明这是产品证据缺口而不是文案问题）。

## 规则检查器（1 个子智能体）

带日期核对当前站点规则；规则会变（例：2025-07-27 起美国站 Title 上限 75 字符），不凭记忆。

检查项：Title 与 Item Highlight 字符数与上限、禁用字符与促销语、重复词、竞品名、"唯一/最佳/首创"类比较词、医学/安全类承诺、A+ 比较图只限同品牌、重要信息不只在图片里、ALT 描述画面而非藏卖点、属性与文案一致（Back Style、材质、产地）。

输出：每稿命中清单 + 修改建议 + 规则来源与日期。

## 主智能体裁决

1. 读三份买家评审、真相与规则结果。
2. **选一个主方向**（通常是买家排序综合最高且 FAIL 最少的稿），写明另外三稿的淘汰理由（一句话各一条）。
3. 从落选稿里**吸收具体句子**（通常：W4 的 Title 结构或 A+ 标题、W3 的边界句、W2 的替代方案句），记录来自哪稿。**W4 必须被审视一次**：写下吸收了哪一处，或为什么一处都不吸收；否则破惯例稿永远进不了成品。
4. 不做平均拼接：五点每条只能有一个主线；不把两稿的 B1 合成一条。
5. 不把几个方案丢给用户自选。用户要选的只是第二轮里的真实分歧。
6. 写融合稿 v1 + 第二轮题包（见 02）。

## 裁决时的判断信号

- 主力买家与"不该买的人"排序**相反**的稿子：最有信息量，通常说明某句既是卖点又是误导，要改写成条件句而不是删。
- 三个买家都跳过的句子：先改写一次（换成动作或条件句）再决定删不删；它可能是唯一的差异化句，只是写得像说明书。
- 真相检查器跨稿共同的 CANDIDATE：这是员工任务，不是文案问题；进核实清单。
- 规则检查器在所有稿都命中同一项：任务书里的上限写错了，修任务书。

## 降级声明

子智能体不可用或被拦截时，主智能体依次自己做评审，并在 HTML 的"发布前检查"里写明："<角色> 由主智能体代做，非独立评审"。不得声称完成了独立多智能体评审。
