# 06 · 字段分工、字符预算与 A+ 交接

## 字段分工

| 字段 | 职责 | 不做什么 |
|---|---|---|
| Title | 识别 + 关键选择信息（品牌、品类主词、pack、核心结构词） | 不放限制条件、不放会降低点击的负面词（老板判断优先） |
| Item Highlight | 补 Title 没答的最高价值事实 / 用途 / 作用；成句，不是逗号规格串 | 不重复 Title 词 |
| 五点 | 每条一个买家问题：价值 → 机制 → 选对 → 证明 → 顾虑；限制条件紧挨对应功能 | 不写五条同一件事 |
| Product Description | 把五点串成一段有顺序的话：先动作场景，再选择，再边界 | 不新增五点没有的主张 |
| 图片 | 演示：每张回答一个买家问题，图上英文 ≤ 12 词 | 重要文字不只在图片里 |
| ALT | 描述画面本身 | 不藏卖点 |
| A+ | 深化证明与选择，首屏一句动作 + 一句边界 | 不重新定位 |
| 属性 | 与文案一致的结构化事实 | 不空着让 AI 猜 |
| Q&A / 差评回复模板 | 老板口述、暂无书面证据的事实（换供应商、旧版本差异） | 不进 Title / 五点 |

不存在通用的 `subtitle` / `item_subtitle` 字段；Item Highlight 是真实字段，按当前站点能力使用。

## 字符预算：尽量用满

Title 与 Item Highlight 是搜索匹配面，**目标用满当前上限**（老板要求：用满换曝光），用真实搜索联想词补位。这是写稿目标，不是校验门槛；publish-gate 不按字符率判定。

规则：
1. 上限在阶段 0 带日期查一次，阶段 5 规则检查器复核；两者不一致以复核为准并改任务书（例：2025-07-27 起美国站 Title 75 字符、Item Highlight 125 字符）。不凭记忆。
2. 补位词来自问题库 C 节的搜索联想（如 `with built in bra`、`seamless`、`for sleeping`、`for layering`），要**成句嵌入**，不做词串；不重复同一个词。
3. **child Title 给系统追加的变体后缀留位**：亚马逊会在 child 标题后追加尺码/颜色（"… Medium"）。先在 Manage Inventory 确认追加部分是否计入上限；未确认时 child 留 3–5 字符余量，Parent 可用满。
4. Highlight 用满后零余量，定稿后不再加字。
5. 用满不等于塞满：如果补位词让句子不像人话，宁可少 3 个字符。
6. 老板明确不要进 Title 的词（如影响转化的限制词），放 Highlight 末尾或对应五点，不放 Title。

## 定稿三通道

| 通道 | 定义 | 去向 |
|---|---|---|
| SAFE | 每句 fact 已证 | 可直接进正式 Bundle（publish-gate） |
| CANDIDATE | 含 NEEDS PROOF 或仅观察事实 | 附员工核实动作 + 降级句；核实后升 SAFE |
| HOLD | 当前不可用 | 附原因；不进任何消费者文案 |

## 交付 HTML 结构（全宽、只读、可展开）

0. 版本与决策记录（每轮老板回答 → 改了什么）
1. 推荐首屏（Title / Parent Title / Highlight / 五点 / Description / A+ 首屏，各附字符数）
2. 产品认识与页面问题
3. 竞争取舍表
4. 主购买理由与淘汰路线（四稿各一句淘汰理由）
5. 老板回答改变了哪些句子
6. 三通道文案（SAFE / CANDIDATE / HOLD）
7. 图片构想与 ALT
8. A+ 交接简报
9. 答案地图
10. Q&A / 差评回复模板
11. 员工核实清单（P0 阻塞发布 / P1 不阻塞）
12. 禁用声明（HOLD 词表）
13. 发布前检查（含降级声明）

HTML 无表单、无提交按钮、无可编辑事实、无线上账号控件。壳文件：`assets/listing-staff-entry-shell.html`。生成后在回复里给绝对路径；有图形界面的环境可以顺手打开，无界面（Codex 沙箱等）只给路径。

## A+ 交接简报（给 `$amazon-premium-aplus-planner`，嵌入式）

交接内容：产品意图简报 · 胜出方向与淘汰理由 · 事实台账（含三档）· 字段分工（Listing 已经答了哪些问题，A+ 该深化哪些）· 答案地图中标记"A+ 承担"的行 · 图片素材现状与预算 · 老板第二轮决定。

A+ 规划器**不重新访谈、不重新定位、不复活落选方向、不扩大 child/pack 范围**。它返回模块级设计、Brand Story、视觉简报、模块能力核查；发现事实缺口时以"证据请求"形式返回给本 Skill，不自行补事实。

交接简报本身就是 embedded 的触发条件，不需要先有 FROZEN 状态。需要正式 Handoff v1.1、Bundle、协调器与回执账本时（preflight / 发布支持），读 `$amazon-listing-publish-gate` 的 `listing-decision-atoms-and-handoff-v11.md`；工作稿阶段不需要。
